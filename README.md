## 1. Что умеет

### Запуск

* **Заставка в два такта:** сначала маленький белый круг с чёрным вращающимся индикатором,
  затем он разворачивается в карточку заставки — логотип, «Финансы · две компании»,
  полоса загрузки и версия. Когда интерфейс готов, карточка плавно гаснет и появляется
  программа (без белой вспышки и «прыжков» вёрстки). Ветка `prefers-reduced-motion`
  замедляет анимации.

### Главное (dashboard)

* Два **раздельных остатка на сейчас** по двум компаниям вместе (не зависят от выбранного
  периода — в кассе лежит то, что есть):
  * **Наличные в кассе** — рабочий остаток после НЗ. Это и есть остаток.
  * **На терминале** — отдельной суммой, потому что терминал не остаток: он уходит в банк.
  Складывать их в одно число приложение больше не пытается.
  НЗ показан отдельно — «в НЗ отдельно 201 400 ₽» — и в остаток не входит: это отложенные
  деньги, а не рабочие.
* Четыре метрики за период: **итог, комиссия, расходы, заработано** (`итог − комиссия −
  расходы`; НЗ заработок не уменьшает — это отложенные деньги, а не трата).
* Карточки **«Затон Рыбака»** и **«Арт Фокус»** — **остаток в кассе** (только наличные,
  без терминала) и мини-метрики «на терминале (уходит в банк) / в НЗ / итог / заработано»,
  количество записей.
* Показатели считаются и **раздельно по компаниям, и суммарно**.
* Переключатель периода: этот месяц / прошлый месяц / 30 дней / всё время.
* Сравнение двух месяцев: итог, расходы и заработано для обеих компаний вместе и для каждой
  отдельно. Сравниваются одинаковые числа дней; когда прошлый месяц короче, текущий обрезается
  до такого же числа дней. Будущие дни не входят, нет записей дня — разница не показывается.
  Количество записей и движений видно рядом: пропущенные дни автоматически не восполняются.
* График итога за 14 дней с разбивкой по компаниям и подсказками при наведении.
* Блок «Последние записи» и «Движения денег» — переход в редактирование одним щелчком.

### Запись дня

Весь день — на одном экране, без прокрутки и лишних карточек:

1. **Компания и дата** в одну строку: две пилюли компаний и дата «6 ноября 2026, пт»
   с переходом «‹ день ›»; по клику на дату открывается свой чёрно-белый календарь
   (не системный попап браузера).
2. **Четыре денежных поля в ряд**, в том порядке, в котором идут деньги за день:
   терминал → касса вчера → факт в кассе → НЗ. Под каждым — одна короткая подсказка
   (комиссия с терминала, изменение наличных, «без комиссии» для НЗ).
3. **Расходы** — компактные строки «сумма + на что и куда», итог расходов в заголовке.
4. **Комментарий** — необязательная заметка в одну строку.

Внизу липнет **панель действий**: итог дня крупно, рядом терминал, наличными, комиссия и НЗ,
справа — «Удалить», «Сбросить» и главная кнопка («Сохранить день» / «Обновить запись»).
Кнопку сохранения не нужно искать прокруткой.

* Две кнопки выбора компании с подсветкой активной — **все записи дня сохраняются
  под выбранной компанией**.
* **Остаток наличных вчера** — подставляется автоматически из фактического остатка последней
  записи компании (с учётом движений денег между записями), но остаётся редактируемым
  и сохраняется в записи. Кнопка «Подставить N ₽» возвращает подсказанное значение.
* **Сумма по терминалу**, **факт наличных в кассе**, **положено в НЗ** — отдельные поля.
  Расходы из фактических денег **не вычитаются**: они уже физически ушли из кассы.
* Блок расходов: сумма + комментарий «на что и куда», любое количество строк за день.
* Выбор даты с переходом «‹ день ›» и кнопкой «Сегодня».
* Панель «Итог дня» пересчитывается на лету: `итог = терминал + наличными`, где
  `наличными = нал вечером + расходы − остаток вчера`. Рядом — комиссия и «Заработано»
  (`итог − комиссия − расходы`): только там с терминала снимается комиссия банка.
* «Сохранить день» фиксирует запись с датой; повторное сохранение того же дня обновляет
  существующую запись (дублей не бывает).

### Поступления и изъятия

* Отдельное окно для денег, которые **не входят в итог дня**: внесли наличные в кассу,
  забрали на счёт, доложили на терминал, отложили в НЗ.
* Форма: компания, дата, куда (наличные / терминал / НЗ), направление (положить / забрать),
  сумма, комментарий и живой прогноз влияния на свободный остаток.
* Движения **не меняют итог и заработок** — только остатки на главном экране; подпись
  прогноза зависит от того, куда двигаются деньги («влияние на остаток в кассе» или
  «влияние на терминал»).
* Поступления через терминал облагаются комиссией банка, изъятия — нет.
* Журнал с фильтрами по компании, цели и периоду, удаление с подтверждением, экспорт CSV.

### История

* Фильтры по компании, периоду, диапазону дат (через тот же календарь) и поиск по комментариям.
* Карточка записи показывает все поля: остаток вчера, терминал, факт в кассе,
  остаток вчера, нал вечером, изменение наличных, расходы, НЗ, комиссию, итог дня и заработок.
* Сводка по выборке: итог, комиссия, расходы, НЗ, заработано за период, остаток в кассе
  и отдельно «на терминале».
* Раскрывающийся список расходов, редактирование и удаление с подтверждением.
* Блок движений денег за период и экспорт **только текущей выборки** в CSV, который Excel
  открывает без «кракозябр».

### Настройки

* **Ставка комиссии банка** — по умолчанию 2,75%, меняется в любой момент; все расчёты
  пересчитываются сразу.
* Две чёрно-белые темы в духе X: **«Чёрная»** (#000000, по умолчанию) и **«Белая»**
  (#FFFFFF); переключаются в настройках и кнопкой в сайдбаре.
* Путь к файлу данных, кнопка «Открыть папку с данными».
* Резервная копия в JSON: выгрузка и восстановление.
* Очистка всех записей с подтверждением.
* Справка по формулам расчёта, статистика по записям и движениям, информация о версии.

### Общее

* Автоматический пересчёт всех сводных показателей после любой записи, правки, удаления
  или импорта.
* Всё на русском языке, суммы в рублях с копейками, даты в формате ДД.ММ.ГГГГ и «5 ноября 2025».

## 2. Технологический стек и почему он

**Electron 45 + React 19 + TypeScript 5.9 + Vite 8, сборка electron-builder
(NSIS-установщик + portable .exe).**

Задача требует одновременно точного воспроизведения фирменного стиля X (скругления, тонкие
обводки, крупные жирные цифры, кастомные ховеры, линейные SVG-иконки) и готового установщика
`.exe`, собираемого на Windows-раннере GitHub Actions за один шаг. Electron даёт Chromium,
поэтому весь дизайн-язык X переносится в CSS 1:1, а весь интерфейс пишется на React с
типизацией; файловая система и диалоги сохранения доступны через IPC из main-процесса без
нативных модулей. `electron-builder` одной командой выдаёт NSIS-установщик и portable-версию,
не требуя Visual Studio, .NET SDK или Rust-тулчейна (Tauri/WPF упёрлись бы в необходимость
Rust/Windows для сборки, Python + CustomTkinter — в ручную стилизацию виджетов и хрупкую
упаковку в exe). Цена выбора — размер дистрибутива ~90–120 МБ, что для десктопного трекера
приемлемо.

Подробности архитектуры, схема слоёв и таблица дизайн-токенов — в [ARCHITECTURE.md](ARCHITECTURE.md).

## 4. Запуск из исходников

Нужны **Node.js 22+** и npm.

```bash
git clone https://github.com/gjjut/Proga.git
cd Proga
npm ci

# вариант 1: приложение целиком (Electron + Vite dev-сервер)
npm run dev

# вариант 2: только интерфейс в браузере (данные в localStorage, демо-набор для наглядности)
npx vite
```

Полезные команды:

| Команда | Что делает |
|---|---|
| `npm run dev` | Сборка main-процесса, Vite-сервер и окно Electron с горячей перезагрузкой интерфейса |
| `npm run typecheck` | Проверка типов рендерера и main-процесса |
| `npm test` | 78 тестов: расчёты, миграция модели, форматирование, CSV, прогон интерфейса в jsdom |
| `npm run build` | typecheck + тесты + сборка `dist-renderer` и `dist-electron` |
| `npm run icon` | Перегенерировать `assets/icon.png` |
| `npm run dist` | Собрать установщик и portable .exe в `release/` |
| `npm run bump patch` | Поднять версию и обновить CHANGELOG (см. [раздел 13](#13-как-выпускать-обновления)) |

## 6. Модель данных и формулы

Одна запись — **один день одной компании**. Инвариант: уникальная пара (`company`, `date`).

```jsonc
{
  "schemaVersion": 2,
  "records": [
    {
      "id": "uuid",
      "company": "zaton",             // 'zaton' | 'artfokus'
      "date": "2026-11-05",           // локальная дата, YYYY-MM-DD
      "cashPrev": 10000,              // остаток наличных предыдущего дня (подставляется, но редактируется)
      "terminal": 48200,              // сумма по терминалу за день
      "cashFact": 9600,               // фактическое наличие денег в кассе на конец дня
      "reserve": 4500,                // отложено в НЗ (без комиссии)
      "expenses": [
        { "id": "uuid", "amount": 3400, "comment": "Корм и прикормка" }
      ],
      "note": "Две группы рыбаков",
      "createdAt": "2026-11-05T19:40:00.000Z",
      "updatedAt": "2026-11-05T19:40:00.000Z"
    }
  ],
  "adjustments": [
    {
      "id": "uuid",
      "company": "zaton",
      "date": "2026-11-06",
      "target": "cash",               // 'cash' | 'terminal' | 'reserve'
      "direction": "in",              // 'in' — положили, 'out' — забрали
      "amount": 15000,
      "comment": "Внесли личные деньги",
      "createdAt": "2026-11-06T09:00:00.000Z"
    }
  ],
  "settings": { "theme": "black", "lastCompany": "zaton", "commissionRate": 2.75 }
}
```

| Показатель | Формула |
|---|---|
| Изменение наличных | `cashFact − cashPrev` |
| Нал вечером | `cashFact` — **весь** нал, который насчитали в кассе, вместе с отложенным в НЗ |
| В кассе после НЗ | `нал вечером − reserve` — этот остаток переходит на следующий день |
| Итог наличными | `нал вечером + Σ expenses[].amount − cashPrev` |
| **Итог дня** | `terminal + итог наличными` = `terminal + нал вечером + расходы − остаток вчера` |
| **Комиссия банка** | `terminal × commissionRate / 100` (по умолчанию 2,75%), на НЗ и наличные не начисляется |
| НЗ дня | `reserve` (деньги ушли из кассы, но остались вашими) |
| **Заработано за день** | `итог − комиссия − расходы` |
| То же короче | `terminal − комиссия + изменение наличных + reserve` (расходы уже внутри кассы) |
| **Заработано за период** | `Σ итога дней − комиссия − расходы` (движения денег не считаются заработком) |
| Наличные в кассе | `cashFact` последней записи компании ± движения по кассе и НЗ после неё |
| Движение в НЗ | положили — `касса −amount`, `НЗ +amount`; забрали — наоборот. Итог остатка не меняется: деньги переехали |
| На терминале | `Σ terminal − комиссия банка ± пополнения/изъятия терминала`. **Не остаток**: эти деньги уходят в банк, поэтому на Главном стоят отдельной суммой |
| **Остаток в кассе** | `наличные после НЗ` — состояние **на сейчас**, от периода не зависит; НЗ показывается отдельно |
| Комиссия по движению | только `target = 'terminal'` и `direction = 'in'`: `amount × commissionRate / 100` |

Расходы **добавляются** в итог только затем, чтобы восстановить проданное за наличные (деньги
ушли из кассы, значит в вечернем нале их уже нет), и тут же **вычитаются**. Поэтому заработок
от расходов не растёт: потратил — значит этих денег нет.

**НЗ — не расход.** Отложенные в запас деньги остаются вашими, поэтому заработок они не
уменьшают. Но и в кассе они не остаются: «нал вечером» — это весь нал целиком (вместе с НЗ),
а рабочий остаток = `нал вечером − НЗ`. Поэтому на Главном виден именно рабочий остаток,
а НЗ — отдельной строкой вне остатка. Итог: `остаток + НЗ = стартовая касса + заработано
за всё время ± движения денег`; расхождение означает потерянную запись.

Движения денег (`adjustments`) **не попадают** ни в итог, ни в заработок: это перекладывание
уже заработанных денег. Они меняют только остатки. Движения с датой **позже** последней записи
компании сразу видны в «наличных в кассе»; движения внутри уже записанных дней не учитываются
повторно — они и так попали в `cashFact`. Комиссия с поступлений через терминал при этом
уменьшает заработок: банк действительно удержал эти деньги.

**Касса переходит из дня в день по цепочке.** Поле «Касса вчера» подставляется из остатка
прошлой записи компании (± движения по кассе и НЗ между днями), а «Нал в кассе» — это весь нал
вечером вместе с НЗ; на завтра переходит `нал − НЗ`. Если цепочка рвётся (кто-то вписал
остаток руками), деньги в отчётах «прибавляются» или пропадают — на Главном появляется
предупреждение с точной датой и разницей, а в «Записи дня» кнопка «В прошлой записи … —
подставить». В демо-данных цепочка сходится всегда.

**Пример.** Вчера в кассе 10 000 ₽, терминал 48 200 ₽, вечером насчитали 14 100 ₽
(из них 4 500 ₽ отложили в НЗ), расходы 3 400 ₽. Тогда: в кассе после НЗ 9 600 ₽,
изменение наличных −400 ₽, **итог наличными = 14 100 + 3 400 − 10 000 = 7 500 ₽**,
**итог дня = 48 200 + 7 500 = 55 700 ₽**, комиссия **1 325,50 ₽**,
**заработано 55 700 − 1 325,50 − 3 400 = 50 974,50 ₽**. НЗ в заработке не участвует:
4 500 ₽ лежат отдельно и видны в остатках (то же короче: 48 200 − 1 325,50 − 400 + 4 500).

**Простой пример на пальцах.** Вчера в кассе 1 000 ₽, сегодня вечером насчитали 2 000 ₽ и
отложили 500 ₽ в НЗ. Значит в кассе после НЗ — 1 500 ₽, на Главном видно 1 500 ₽ (а НЗ — 500 ₽
отдельной строкой), а итог дня = 2 000 − 1 000 = 1 000 ₽.

Все показатели пересчитываются на лету из массива записей и движений (`src/lib/calc.ts`) —
поэтому любая правка, удаление или импорт сразу меняют и карточки, и историю, и график.

**Миграция.** Старые файлы (`schemaVersion: 1`) читаются без потерь: поле `cash` становится
`cashFact`, `cashPrev` при первом чтении подставляется из предыдущей записи той же компании,
`adjustments` создаётся пустым, ставка комиссии — 2,75%. Схема поднимается до версии 2
при следующем сохранении.

## 7. Где хранятся данные

| Режим | Путь к файлу |
|---|---|
| Портативная версия | `<папка с .exe>/data/finance-data.json` |
| Установленная версия | `%APPDATA%\ZatonFinance\finance-data.json` |

* Перед перезаписью существующего файла создаётся `finance-data.backup.json` —
  предыдущая версия данных. При первом сохранении резервной копии ещё нет.
* Запись выполняется через временный файл и переименование; это снижает риск частичной
  записи, но не заменяет отдельные резервные копии (например, при сбое диска).
* Если основной файл повреждён, приложение восстанавливает исправную резервную копию,
  сохраняет оригинал рядом как `finance-data.json.corrupted-…` и предупреждает, что
  последние изменения могут отсутствовать. Проверьте данные и выгрузите отдельную копию.
* Если восстановление невозможно, работа с данными блокируется, исходные файлы не
  перезаписываются. Откройте папку данных с экрана ошибки и сохраните файлы для восстановления.
* Путь всегда виден в «Настройки → Данные», там же кнопка «Открыть папку с данными».
* В версии для Windows создаются автоматические копии в подпапке `backups`: при запуске,
  после изменения данных и раз в час, пока программа открыта. Хранятся первая и последняя
  копии за каждую из последних 30 дат, а также отдельные копии перед удалением и восстановлением.
  В настройках можно выбрать другую папку: программа создаст в ней `ZatonFinance-backups`.
  Для облачного хранения выберите папку синхронизации, но проверяйте синхронизацию самостоятельно.
  Копии не зашифрованы. При недоступной папке появится предупреждение; удаление и
  восстановление блокируются, пока нельзя сохранить копию до изменения данных.
* В браузерном режиме автоматических копий нет.
* Для бэкапа или переезда на другой компьютер: «Скачать резервную копию» / «Загрузить копию».

**Ручной чек-лист перед релизом**

1. Записать день для «Затон Рыбака»: остаток вчера подставился сам, заработано = терминал +
   (факт − остаток вчера) + расходы, комиссия = терминал × 2,75%.
2. Записать тот же день для «Арт Фокус» → появились две отдельные записи.
3. Сохранить день повторно → запись обновилась, дубля нет; остаток вчера подставляется
   из предыдущего дня той же компании.
4. Удалить запись → сводка пересчиталась.
5. «Поступления»: положить 15 000 ₽ в наличные → свободный остаток и наличные выросли,
   итог не изменился. Положить 10 000 ₽ через терминал → остаток вырос на 9 725 ₽
   (за вычетом комиссии 2,75%), итог снова не изменился.
6. История → фильтры по компании/датам (календарь «с»/«по»)/поиску работают,
   «Экспорт в Excel (CSV)» открывается в Excel с правильной кодировкой, разделителями
   и блоком движений.
7. Настройки → переключение «Чёрная» / «Белая», ставка комиссии 3,5% меняет все расчёты,
   «Скачать резервную копию» → «Загрузить копию».
8. Закрыть и открыть приложение → данные на месте (файл из раздела 7).

## 11. CI/CD: как работает автоматический релиз

### `.github/workflows/ci.yml`

На каждый push в `main`, pull request и ручной запуск: `npm ci` → `typecheck` → `npm test` →
сборка рендерера и main-процесса. Красный CI = не мержим.

### `.github/workflows/release.yml`

Триггер: **push тега `v*`** (например `v1.0.1`) или ручной запуск (`workflow_dispatch`).

Шаги на `windows-latest`:

1. `actions/checkout` + `actions/setup-node` (Node 22, кэш npm).
2. Кэш Electron/electron-builder — повторные сборки быстрее.
3. `npm ci`.
4. **Проверка, что тег совпадает с `version` в package.json** — защита от релиза «не той» сборки.
5. `npm run typecheck` и `npm test` — релиз не выйдет с падающими тестами.
6. `npm run icon` и `npm run dist` — electron-builder собирает NSIS-установщик и portable .exe.
7. `node scripts/changelog-section.mjs release-notes.md` — заметки релиза из CHANGELOG.md.
8. `actions/upload-artifact` — артефакты доступны даже при ручном запуске.
9. `softprops/action-gh-release` — создаёт **GitHub Release**, прикрепляет
   `ZatonFinance-Setup-<версия>.exe` и `ZatonFinance-Portable-<версия>.exe`, публикует заметки.

Итог: одно нажатие `git push origin v1.0.1` — через несколько минут на странице Releases
лежит готовый к скачиванию `.exe`.

## 12. Пошагово: репозиторий, Actions, первый релиз

Код уже лежит в репозитории `gjjut/Proga`. Ниже — полный путь с нуля, если понадобится
повторить на новом аккаунте.

### Шаг 1. Создать репозиторий

```bash
# на github.com: New repository → имя Proga → Private/Public → без README и .gitignore
git remote add origin https://github.com/<ваш-логин>/Proga.git
# или, если репозиторий уже есть:
git remote set-url origin https://github.com/<ваш-логин>/Proga.git
git remote -v
```

### Шаг 2. Залить код

```bash
git add .
git commit -m "feat: финансовый трекер для двух компаний"
git branch -M main
git push -u origin main
```

`package-lock.json` обязательно должен попасть в коммит — workflow использует `npm ci`.

### Шаг 3. Включить Actions и разрешить публикацию релизов

1. Вкладка **Settings → Actions → General → Actions permissions**:
   выберите **Allow all actions and reusable workflows** → **Save**.
2. Там же **Workflow permissions**: включите **Read and write permissions**
   (это нужно шагу, который создаёт Release и загружает .exe) → **Save**.
   Отдельный PAT не требуется: используется встроенный `GITHUB_TOKEN`.
3. Вкладка **Actions**: если workflow'ы отключены, нажмите **I understand my workflows, go ahead
   and enable them**.

### Шаг 4. Проверить сборку (ещё без релиза)

Запустите CI: **Actions → CI → Run workflow** (или сделайте любой push в `main`).
Через 2–4 минуты все шаги должны быть зелёными.

Можно проверить и релизный workflow без публикации: **Actions → Release → Run workflow** —
соберутся артефакты, а шаг публикации пропустится (он запускается только для тегов).

### Шаг 5. Выпустить первый релиз

Версия в `package.json` уже `1.0.0`, CHANGELOG содержит описание 1.0.0:

```bash
git tag -a v1.0.0 -m "v1.0.0 — первый релиз"
git push origin v1.0.0
```

Что произойдёт:

1. Запустится **Release** workflow.
2. Пройдут проверка тега, типы и тесты.
3. `electron-builder` соберёт `ZatonFinance-Setup-1.0.0.exe` и `ZatonFinance-Portable-1.0.0.exe`.
4. Создастся GitHub Release `v1.0.0` с описанием из CHANGELOG и обоими файлами.
5. Ссылка для скачивания появится в разделе **Releases** вашего репозитория.

### Шаг 6. Первый запуск приложения

1. Скачайте `ZatonFinance-Setup-1.0.0.exe` из Releases.
2. Запустите, при предупреждении SmartScreen — «Подробнее» → «Выполнить в любом случае».
3. Откроется «Главное» с пустой сводкой → «Записать день» → заполните суммы и расходы →
   «Сохранить день».
4. Проверьте: карточка компании, блок «Итого» и график обновились; в «Истории» появилась запись;
   «Настройки → Данные» показывают путь к файлу.

## 13. Как выпускать обновления

```bash
# 1. Внесите изменения в код.
# 2. Опишите их в CHANGELOG.md в разделе [Unreleased].
# 3. Поднимите версию: скрипт обновит package.json и перенесёт [Unreleased] в новый раздел.
npm run bump patch        # 1.0.0 → 1.0.1  (или minor / major / явная версия 1.2.0)

# 4. Закоммитьте и отправьте тег — этого достаточно, релиз соберётся сам.
git add package.json CHANGELOG.md
git commit -m "release: v1.0.1"
git tag -a v1.0.1 -m "v1.0.1"
git push origin HEAD --tags
```

Одной командой (скрипт сам коммитит и ставит тег):

```bash
npm run bump minor -- --tag
```

Правила версий (SemVer): **patch** — исправления, **minor** — новые возможности,
**major** — несовместимые изменения формата данных.

> ⚠️ **Тег нужно ставить на «живой» коммит.** GitHub не запускает workflow для коммитов,
> в сообщении которых есть `[skip ci]` — такой тег создаст релиз-тег без сборки.
> Скрипт `npm run bump -- --tag` всегда тегирует свой коммит, а вручную лучше брать
> merge-коммит PR или коммит с кодом. Если тег уже поставлен на «пустой» коммит:
>
> ```bash
> git push origin :refs/tags/v1.2.0 && git tag -d v1.2.0
> git tag -a v1.2.0 -m "v1.2.0" <merge-коммит> && git push origin v1.2.0
> ```

Файл данных переживает обновления: новая версия просто читает тот же
`finance-data.json`, а `normalizeData()` доводит его до актуальной схемы.

## 14. Частые проблемы

| Симптом | Решение |
|---|---|
| «Windows защитила ваш компьютер» при запуске | Сборка без платной подписи кода. «Подробнее» → «Выполнить в любом случае». Пропадает после покупки сертификата и настройки `certificateFile` в electron-builder. |
| Actions падает с `npm ci` и ошибкой lock-файла | В репозиторий не попал `package-lock.json`. Выполните `npm install` и закоммитьте его. |
| Workflow не запускается по тегу | Тег должен начинаться с `v` (`v1.0.0`, а не `1.0.0`) и быть отправлен (`git push origin v1.0.0`). |
| Release не создаётся, хотя сборка прошла | В **Settings → Actions → General** не включены Read and write permissions. |
| Ошибка «Версия в package.json не совпадает с тегом» | Тег ставили, не подняв версию. Выполните `npm run bump patch`, затем новый тег. |
| Антивирус ругается на portable .exe | Особенность неподписанных portable-сборок Electron; используйте установщик или добавьте файл в исключения. |
| Где данные у portable-версии | В папке `data` рядом с `.exe`. Перенесли exe — перенесите и папку `data`. |
| Нужно переехать на другой компьютер | «Настройки → Скачать резервную копию» на старом, «Загрузить копию» на новом. |
| Запись за день «не сохраняется второй раз» | Так и задумано: одна запись на день и компанию. Повторное сохранение обновляет её. |
| В браузере показываются демо-данные | Это превью-режим (`npx vite`): данные в localStorage и демо-набор для наглядности. Настоящее приложение в Electron начинается с пустого файла. |
