# Архитектура приложения «Финансы компаний»

Локальный финансовый трекер для двух компаний — **«Затон Рыбака»** и **«Арт Фокус»**.
Без сервера, без аккаунтов, без интернета: все данные лежат в JSON-файле рядом с приложением
(портативная версия) или в `%APPDATA%` (установленная версия).

---

## 1. Выбор технологического стека

**Выбран Electron + React + TypeScript + Vite, сборка через electron-builder (NSIS + Portable).**

Обоснование одним абзацем: задача требует одновременно (а) точного пиксельного воспроизведения
фирменного стиля X/Twitter — скругления, тонкие обводки, крупные жирные цифры, кастомные
ховеры, SVG-иконки, — и (б) готового установщика `.exe` плюс портативного `.exe`, собираемого
на Windows-раннере GitHub Actions за один шаг. Electron даёт браузерный движок Chromium, поэтому
весь дизайн-язык X переносится в CSS 1:1, весь UI пишется на React с типизацией, а файловая
система, диалоги сохранения и путь к данным доступны через IPC из main-процесса без нативных
модулей. `electron-builder` одной командой выдаёт `NSIS-установщик` и `portable.exe`, не требуя
Visual Studio, .NET SDK или Rust-тулчейна (Tauri/WPF упёрлись бы в необходимость Rust/Windows
для сборки, Python + CustomTkinter — в ручную стилизацию виджетов и хрупкую упаковку в exe).
Цена выбора — размер дистрибутива (~90–120 МБ), что для десктопного трекера приемлемо.

Альтернативы и почему нет:

| Вариант | Почему не выбран |
|---|---|
| Tauri + React | Меньше размер, но сборка требует Rust-тулчейна и WebView2 на целевой машине; CI дольше и капризнее. |
| WPF (.NET) | Только Windows, точная передача стиля X (градиенты, радиусы, тени, hover) — ручная работа со стилями, нет React-экосистемы. |
| Python + CustomTkinter | Стилизация ограничена, крупные цифры/скруглённые карточки/ховеры делаются вручную, упаковка в exe через PyInstaller хрупкая. |

## 2. Слои приложения

```
┌─────────────────────────────────────────────────────────────┐
│ Renderer (Chromium)                                          │
│  React 19 + TypeScript + CSS                                  │
│  Главное · Запись дня · История · Настройки                   │
│  Состояние — DataProvider (Context), расчёты — lib/calc.ts    │
└───────────────────────────▲─────────────────────────────────┘
                            │ window.finance (contextBridge, типизированный API)
┌───────────────────────────▼─────────────────────────────────┐
│ Preload (изолированный мир, sandbox: true)                    │
│  Только ipcRenderer.invoke, никакого Node API в UI            │
└───────────────────────────▲─────────────────────────────────┘
                            │ IPC (каналы data:*, app:*, window:*)
┌───────────────────────────▼─────────────────────────────────┐
│ Main (Node.js)                                               │
│  electron/main.ts   — окно, меню, диалоги, single-instance    │
│  electron/store.ts  — чтение/запись JSON, атомарно + бэкап    │
└─────────────────────────────────────────────────────────────┘
                            │
                     finance-data.json
```

Разделение ответственности:

* **main** — единственный владелец файла данных. Любая мутация сериализуется (очередь записи),
  пишется атомарно через временный файл + `rename`, перед записью делает `.backup.json`.
* **preload** — публикует узкий типизированный API (`FinanceApi` из `shared/api.ts`), никакой
  `require` в рендерер не попадает.
* **renderer** — вся логика представления и расчётов; не знает про файловую систему. В браузере
  (режим разработки/превью) тот же интерфейс реализуется адаптером на `localStorage`.

## 3. Модель данных

```ts
type CompanyId = 'zaton' | 'artfokus';   // «Затон Рыбака» | «Арт Фокус»
type ThemeMode = 'dim' | 'black';        // #15202B | #000000

interface Expense {           // строка расхода внутри дня
  id: string;
  amount: number;             // ₽, >= 0
  comment: string;            // «на что и куда»
}

interface DayRecord {         // одна запись = один день одной компании
  id: string;
  company: CompanyId;
  date: string;               // YYYY-MM-DD (локальная дата)
  terminal: number;           // сумма по терминалу — выручка дня
  cash: number;               // остаток наличных в кассе на конец дня
  reserve: number;            // сумма, отложенная в НЗ
  expenses: Expense[];
  note: string;               // общий комментарий к дню (опционально)
  createdAt: string;          // ISO
  updatedAt: string;          // ISO
}

interface AppData {
  schemaVersion: 1;
  records: DayRecord[];
  settings: { theme: ThemeMode; lastCompany: CompanyId };
}
```

Инвариант: уникальная пара **(`company`, `date`)**. Повторное сохранение того же дня и той же
компании обновляет существующую запись, а не создаёт дубль (main реализует upsert, рендерер
подхватывает запись в форму и меняет подпись кнопки на «Обновить запись»).

### Формулы показателей

Показатели считаются на лету из массива записей (`src/lib/calc.ts`), поэтому любая правка,
удаление или импорт мгновенно пересчитывают все сводки.

| Показатель | Формула |
|---|---|
| Выручка | `Σ terminal` |
| Расходы | `Σ expenses[].amount` |
| НЗ (неприкосновенный запас) | `Σ reserve` |
| Свободный остаток | `Выручка − Расходы − НЗ` |
| Наличные в кассе | `cash` последней по дате записи компании (это остаток, а не приход) |
| Остаток за день | `terminal − Σ expenses − reserve` |

Показатели считаются отдельно по каждой компании и суммарно по двум компаниям.

## 4. Экраны и навигация

Левое вертикальное меню в стиле X (иконка + подпись):

1. **Главное** — ленточные карточки: сводка «Итого», затем по карточке на компанию
   (выручка, расходы, остаток, НЗ + наличные в кассе), график за 14 дней, последние записи.
   Переключатель периода: всё время / этот месяц / прошлый месяц / 30 дней.
2. **Запись дня** — выбор компании двумя крупными кнопками, дата, три денежных поля,
   динамический список расходов, живой предпросмотр итогов дня, «Сохранить день»,
   удаление/очистка, переход к предыдущему/следующему дню.
3. **История** — фильтры по компании, диапазону дат и поиск по комментариям; сводка по выборке;
   раскрытие расходов; «Редактировать» (открывает запись дня) и «Удалить» (с подтверждением);
   экспорт выборки в CSV для Excel.
4. **Настройки** — тема (Dim / Lights out), путь к файлу данных, открыть папку, резервная копия
   JSON (экспорт/импорт), очистка данных, справка по формулам, версия приложения.

`letter-spacing: -0.02em`; иконки — линейные SVG 24×24 с `stroke-width: 1.75`; скроллбары тонкие.

## 7. Хранение данных и путь к файлу

1. Если задан `PORTABLE_EXECUTABLE_DIR` (запущен portable-сборка) → `<папка exe>/data/finance-data.json`.
2. Иначе → `%APPDATA%/ZatonFinance/finance-data.json` (`app.getPath('userData')`).

Перед каждой записью текущий файл копируется в `finance-data.backup.json`. Запись выполняется
в `finance-data.json.tmp` с последующим `fs.renameSync` — обрыв питания или закрытие окна в момент
сохранения не портит данные. При чтении повреждённый JSON автоматически подменяется бэкапом.

## 8. Релизный конвейер

Тег `v*` → GitHub Actions (windows-latest) → `npm ci` → `typecheck` + `vitest` →
`vite build` + `tsc` (main) → `electron-builder --win nsis portable` → шаг проверки соответствия
тега и `package.json` → GitHub Release с прикреплёнными
`ZatonFinance-Setup-<version>.exe` и `ZatonFinance-Portable-<version>.exe`, телом из CHANGELOG.
